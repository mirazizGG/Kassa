# Оставшиеся задачи

Список получен повторной проверкой **каждой** находки исходного аудита по коду в его
текущем состоянии, а не переписыванием старого отчёта. Из 108 уникальных находок
**48 закрыты** предыдущими правками, **62 остаются открытыми** (после слияния дублей и близких формулировок).
Дополнительно три отдельных прохода искали то, чего в аудите не было: регрессии от самих
правок, готовность к PostgreSQL и деградацию под нагрузкой.

Критических нет. Все три критических из аудита закрыты и покрыты тестами.

| Приоритет | Штук | Смысл |
|---|---|---|
| ~~P0 — блокеры переезда~~ | 0 из 6 | **Закрыто.** Развёртывание возможно |
| ~~P1 — деньги и данные~~ | 0 из 9 | **Закрыто.** Все пути денег покрыты тестами |
| P2 — производительность | 4 из 11 | Осталось: N+1 в истории смен, графики, пагинация клиентов и движений склада |
| P3 — безопасность | 3 из 12 | Осталось: блокировка аккаунта, `is_active` в боте, фильтр админа в трёх отчётах |
| P4 — корректность отчётов | 3 из 10 | Осталось: определение «дня», телефон в боте, COGS |
| P5 — операционные и UX | 8 из 14 | Осталось: недостающие кнопки, посещаемость, задачи, надзор за ботом |

Обозначения трудоёмкости: **S** — до часа, **M** — до дня, **L** — несколько дней.

- **2.4** История смен — N+1 (три агрегата на смену с незамороженными итогами) — **M**
- **2.5** Графики: один запрос на календарный день в цикле Python, `days` не ограничен — **M**

кассы на серверный поиск делает подбор товара зависимым от сети, а это риск для
кассира. Эндпоинт к пагинации уже готов; переключать стоит, когда каталог
перевалит за несколько тысяч позиций.

## P4. Корректность отчётов

Шесть из десяти закрыты.

| | Что было | Чем закрыто |
|---|---|---|
| 4.1 | Напоминания о долге на день раньше | `days_until()` считает **календарные** дни в часовом поясе магазина. `(due - now).days` округлял отрицательный timedelta вниз, поэтому в день срока выходило −1 и клиенту писали «просрочено». Тест |

## Технический долг

- **Alembic вместо ручных `ensure_*`** (M). Механизм рабочий и покрыт тестом на заполненной
  таблице, но при росте числа миграций станет неудобным, а на Postgres требует правки типов (0.3).
- **Дублирование ролевых проверок** (M). `if current_user.role not in [...]` повторяется в
  десятках обработчиков; вынести в зависимость FastAPI.
- **Схемы в двух местах** (S). `suppliers.py` объявляет свои Pydantic-модели вместо
  `schemas.py`, часть на устаревшем `class Config`.
- **Крупные файлы**: `POS.jsx` (~1700 строк), `Employees.jsx`, `Inventory.jsx` — не поддаются
  ревью целиком.
- **Устаревшая документация**: `docs/README.md` описывает интерфейс на Bootstrap и пути
  `/api/*`, которых давно нет.
- **Корневые скрипты**: `test_features.py`, `check_db_lock.py` выглядят рабочими, но ссылаются
  на чужие пути и отсутствующие зависимости. Удалить или починить.

## Как поддерживать список

На каждую правку в денежных путях — тест в `backend/tests/`, названный по дефекту, который
он стережёт. Так устроены существующие 55 тестов. Перед сдачей работы:

    cd backend  && python -m compileall -q . && python -m pytest
    cd frontend && npm run lint && npm run build
